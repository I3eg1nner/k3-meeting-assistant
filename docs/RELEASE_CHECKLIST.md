## 新开发板与固态盘

1. 先检查 `lsblk -f`、`findmnt`、`df -hT`、`free -h` 和现有 service。禁止把“接入固态盘”解释成格式化授权。
2. 确认实际数据目录、模型目录、剩余容量和挂载持久性。服务运行前使用 SQLite backup 备份数据库，并在停服窗口备份上传文件及 `/etc/meeting-assistant.env`，备份不得进入 GitHub。
3. 推荐将 SSD 上的数据目录 bind mount 到 `/var/lib/meeting-assistant`，保持模型适配器和 systemd 写路径兼容。具体源目录和 UUID 必须由现场检查决定，不使用猜测路径。
4. 在 systemd override 中增加 `RequiresMountsFor=/var/lib/meeting-assistant`；SSD 挂载点还应配合 mount unit 依赖，测试拔盘/挂载失败时拒绝启动，避免写满根盘。
5. 完成复制和校验后才切换数据目录；保留原数据，不自动删除。不要启用 Swap 掩盖超限。

部署命令（主机通过环境变量传入，不把密码写入源码）：

```sh
K3_HOST=root@your-host K3_PORT=60022 bash scripts/deploy-k3.sh
```
