# K3 会议智记

面向技术会议与分享的本地图文报告工作台：将录音、文字稿和现场幻灯片整理为可校订、可追溯、适合人类阅读的详细文档。

项目运行在进迭时空 K3 开发板上，面向单用户、会后异步处理。重点不是多生成一份摘要，而是把分散在发言和 PPT 中的信息组织成一份读者能够理解、编辑者能够核对的报告。

> 当前为发布候选，尚未完成产品级验收。本地模型已恢复并完成逐阶段冒烟，自动报告仍需人工校订。结构完整、引用存在或测试通过，都不等于内容准确、信息无遗漏。

[快速开始](#快速开始) · [部署与模型恢复](docs/OPERATIONS.md) · [验收状态](docs/RELEASE_CHECKLIST.md) · [历史实验](docs/VALIDATION_HISTORY.md) · [安全说明](SECURITY.md)

## 适合什么场景

- **技术分享与开放日**：把中英混合讲解、现场 PPT 照片整理成有背景、方法、能力边界和图示说明的技术文稿。
- **方案评审与项目讨论**：提取决定、行动项、风险和未决问题，并保留负责人、时间和原始依据。
- **已有材料的再整理**：导入录音或飞书文字稿，在校对后形成可编辑的 Word 和便于分发的 PDF。

首版不面向实时录音、同声翻译、多租户协作或会议中问答，也不承诺无人审核即可发布。

## 最终交付什么

| 报告深度 | 主要内容 | 适用目的 |
|---|---|---|
| 精简纪要 | 核心议题、决定、行动项与待核实内容 | 快速回顾 |
| 标准报告 | 背景、议题、决定、风险、行动项及证据 | 项目跟进与归档 |
| 技术整理文稿 | 按知识与逻辑关系组织的章节、解释性正文、表格、图片说明及来源附录 | 分享传播与技术阅读 |

详细文稿的目标是让没有参加会议的人也能读懂，而不是把转写按时间顺序拼接起来。报告深度是编排选择，不是补写未知内容的许可；材料不足时应说明缺口，而不是凑字数。

导出支持 DOCX / PDF。读者看到的是章节、图片和清晰的来源编号；编辑者可以回到原始音频片段或图片核对。未经确认的导出标记为草稿，正式导出需要人工审核确认。

## 核心方法

### 1. 同时整理讲解与幻灯片

支持音频、图片及 TXT / Markdown / SRT / VTT 文字稿。音频经过预处理、语音分段、说话人聚类和转写；图片保留原图，结合 OCR 与多模态模型提取文字和解释。

OCR 文字、视觉解释和原始材料分开保存。模糊内容、模型候选和低可信图片关联需要校对，不能因为附有图片就被当作已证实的事实；生成式增强结果不作为文字证据。

### 2. 先建立事实，再组织长文

处理链路为：

```text
录音 / 文字稿 / PPT 照片
        ↓
带时间或图片位置的证据
        ↓
结构化事实与人工校订
        ↓
分章节报告 → 证据与结构检查 → 人工审核 → DOCX / PDF
```

事实包括议题、决定、行动项、风险、问题、指标和术语，并保存来源引用、可信度与人工锁定状态。

当前实现以重叠窗口抽取事实，再为详细文稿组织目录和逐章生成正文，不依赖一个不断压缩的滚动摘要。窗口仍按字符长度估算，材料组织也存在截取，尚不能保证长会议信息完整保留。

### 3. 让校订成果能够保留下来

- 原始转写、自动校正和用户修订分层保存，不覆盖原始识别。
- 修改转写后同步证据，并将受影响事实和报告标记为需要重新核对。
- 支持说话人改名、事实采用或拒绝、事实锁定、图片关联确认。
- 报告保存版本，支持章节重生成；Markdown 编辑保留标题、表格和证据标记。

这套机制的价值是降低核对与返工成本，而不是替代人工判断。

### 4. 把发布检查与生成分开

报告生成后检查来源引用、部分数字一致性、图片关联冲突和文档结构；富材料的技术文稿还设有章节、正文长度及图片覆盖门槛。

这些是必要的机械检查，不是语义正确性的证明。最终仍需人工检查：是否容易理解、是否遗漏重点、数字属于谁、能力边界是否准确、决定是否真正在会上形成。

## 与实时会议助手的关系

[YuMeet](https://github.com/spacemit-com/docs-ai/blob/main/zh/solutions/aicomputer_solution/yumeet.md) 等工具侧重实时转写、翻译和会议总结；本项目侧重会后多模态材料整理、事实校订与详细报告交付。

两者可以互补。本项目的差异化是图文材料与证据工作流，而不是宣称本地运行、模型参数或报告准确率全面领先。目前没有完成与 YuMeet 在同一素材上的效果对测。

## 当前验证到哪一步

以下为 **2026-11-16 的恢复与回归记录**，不是业务准确率认证：

| 检查 | 实测结果 | 不能据此推断 |
|---|---|---|
| 应用回归 | K3 后端 56 项通过；前端 6 项通过；构建、lint、类型检查通过 | 已完成全部产品验收 |
| 文本模型 | Qwen3-4B 20/20 请求完成，JSON 与结构合法率 100%；合成用例语义通过率 75% | 达到 90% 业务召回目标 |
| 音频与说话人 | ASR / VAD、CAM++ 在短会议片段返回非空结果 | 真实会议 CER / DER 达标 |
| OCR 与图片理解 | OCR 单图返回 15 个区域；Qwen3.5-2B 单图返回合法 JSON，无资源违规 | 文字或图像解释全部正确 |
| 部署恢复 | SSD 模型配置、服务重启与鉴权检查通过 | 所有故障回滚路径已验证 |

文本模型该轮峰值进程树 RSS 为 5764MiB，图片理解单样本峰值 RSS 为 4563MiB。运行不依赖 Swap；不同模型、软件版本和素材需要重新测量。

历史内部素材曾经由人工校订形成 26 页图文 DOCX / PDF；这说明人机协作交付路径可行，**不代表模型能独立生成同等质量的报告**。详细数据与失败案例见[历史实验记录](docs/VALIDATION_HISTORY.md)。

- 尚未完成所有启用模型连续 20 样本的完整验收。

- 无人值守详细文稿尚未通过人工语义与可读性验收。
- 强制对齐模型尚未完成部署验收，当前使用 VAD / ASR 句段时间戳。
- 安装仍依赖厂商原生运行时，尚不是面向干净系统的一键产品部署。

## 本地与端云模式

**LOCAL_ONLY**：使用本地推理，不主动外发会议材料。它是当前主要验证路径。

**HYBRID_REVIEW**：已有 OpenAI 兼容适配层和候选结果、外发审计相关结构，但经授权的局部音频与图片裁剪复核流程尚未完成。为避免隐私范围扩大，整段音频或整图的自动兜底外发已关闭。

因此，选择混合模式不等于已经启用成熟的自动云端复核。配置项见 [.env.example](.env.example)，隐私边界见 [SECURITY.md](SECURITY.md)。

## 快速开始

### 开发环境

需要 Node.js 22.13+、Python 3.11+；K3 真机使用系统 Python 以复用厂商推理组件。

```bash
npm ci
python3 -m venv .venv
.venv/bin/pip install -e '.[dev]'

# 终端 1：API
MEETING_DATA_DIR=.data MEETING_STATIC_DIR=backend/static \
  .venv/bin/uvicorn meeting_assistant.main:app --app-dir backend --reload

# 终端 2：Web
npm run dev:k3
```

浏览器访问 `http://localhost:4173`。上述命令启动应用，不会自动安装模型、FFmpeg 或厂商原生运行时；缺少模型时只能验证界面和降级流程，不能获得完整识别能力。

### K3 部署

在开发机构建并上传应用，板端不需要 Node.js：

```bash
K3_HOST=root@your-host K3_PORT=60022 bash scripts/deploy-k3.sh
```

应用位于 `/opt/meeting-assistant`，默认业务数据位于 `/var/lib/meeting-assistant`。模型可独立放到已挂载的 SSD；部署不会自动格式化或迁移磁盘。生产服务要求访问令牌，不应直接暴露到公网。

模型下载、校验、SSD 配置、OpenCV 兼容库、原生适配器及备份回滚说明见[部署与模型恢复](docs/OPERATIONS.md)。首次部署前请逐项阅读，不要把源码上传成功当成推理环境就绪。

## 技术与测试

应用采用 React / FastAPI / SQLite；音频预处理使用 FFmpeg，文本和多模态推理使用 K3 `llama-server`，其他阶段通过命令适配器接入。

当前恢复组合为 Silero VAD、CAM++、Qwen3-ASR-0.6B q40、PP-OCRv5、Qwen3.5-2B 图片理解和 Qwen3-4B Q4_K_M 文本模型。重型推理串行执行，目标保持至少 512MiB 可用内存、模型阶段 RSS 不超过 6.2GiB。应用守护器是采样检查，不等同于内核硬隔离。

```bash
.venv/bin/python -m pytest
npm test
npm run lint
npx tsc --noEmit
```

单元测试与 CI 检查行为和回归；模型基准、真实会议真值评估以及人工逐页审阅分别承担不同的验收职责。具体步骤见[发布检查清单](docs/RELEASE_CHECKLIST.md)。
